=== Slide 2 ===
Introduction



Link adaptation is to adapt the radio link based on current channel condition.
The input parameters for this calculation in DL & UL are CQI and BLER. 
CQI :
In DL, CQI is received in UL UCI indication from PHY.
In UL, CQI is calculated from SINR (SL question: how is this calculation performed????) in UL-SCH data indication & from SRS.
BLER:
In DL, BLER is calculated based on HARQ ACK/NACK received in uplink from PHY.
In UL, BLER is calculated based on CRC-indication of UL-data. (CRC pass - ACK, CRC fail - NACK)

Below are the 2 algorithm used for link Adaptation (As per Radisys code):
CQI Based Link adaptation  :      It will calculate cqiBasedMCS.
BLER Based Link adaptation:     It will calculate deltaMCS.

NOTE : This PPT is only focused on Algorithms assuming that we have calculated or received correct CQI and BLER in both UL & DL. And these algorithms are common for both UL and DL.

=== Slide 6 ===
When CQI report is received from PHY, MAC will calculate the corresponding MCS value based on CQI -to- MCS mapping table prepared in previous slides.

For CQI-Based link adaptation, 
cqiBasedMCS is calculated as : 20% new_MCS * 100 + 80% old_MCS * 100. (during one last CQI report, 80% is considered)
	- the 20% & 80% values are configured as macros, it can be changed.
It is calculated in terms of multiple of 100. Ex : if its 2200 then MCS = 22. 
if it is first CQI report, then store value directly.
If difference between old_MCS & new_MCS is more that 5 then reset Link adaptation Algorithm by setting deltaMCS = 0.
If RI value changes, then reset cqiBasedMCS with new_MCS value calculated based on received CQI.

NOTE : cqiBasedMCS is calculated on every CQI report in UL & DL.  SL comment: there is then an obvious accuracy inconsistency on the algorithm between DL and UL:
DL: according to your algorithm, in DL, CQI is periodically (Jio configurable periodicity) received in UL PUCCH UCI indication from PHY
UL: according to your algorithm, in UL, CQI is calculated from SINR in UL-SCH data (PUSCH) indication & from SRS
Obviously, the periodicity of UL CQI report (Dl case) and UL scheduling grants (UL case) is different  that makes the DL/UL MCS decision uneven.

=== Slide 8 ===
BLER Based Link adaptation (outer loop)
Running “deltaMCS” counter is used to calculate BLER based link adaptation.
When HARQ feedback is received from PHY in DL & UL, MAC will increase or decrease deltaMCS value based on stepsize of ACK and NACK.
On every NACK, deltaMCS is subtracted by “STEP_DOWN_FACTOR” and on every ACK reception deltaMCS is added by “STEP_UP_FACTOR”.
 The value of STEP_UP_FACTOR and STEP_DOWN_FACTOR is calculated (in terms of 100) based on the tolerance level configured from OAM in such a way that  STEP_UP_FACTOR = STEP_DOWN_FACTOR / 10. 
If STEP_UP_FACTOR = 1 & STEP_DOWN_FACTOR = 10 then to compensate 1 NACK, 10 ACKs are required.
deltaMCS is always multiple of 100 (i.e. if deltaMCS = 200  200/100 = 2).

Final_MCS = (cqiBasedMcs + deltaMcs) / 100;
Ex : 
If STEP_UP_FACTOR = 3 & STEP_DOWN_FACTOR = 30.
Then it is required around 34 continuous ACKs to increase MCS by 1, & 4 continuous NACKs to decrease MCS by 1.

 NOTE : BLER Basesd MCS is calculated on every HARQ ACK/NACK reception in UL & DL.

=== Slide 10 ===
BLER Based Link adaptation (outer loop modified SL)
Running “deltaMCS” counter is used to calculate BLER based link adaptation, considering a reinforcement learning RL correction algorithm to compensate for the fast reactions over ACK’ed packets (current implementation is very slow on recovering the selected MCS after few NACK’ed packets – too slow reaction leading into lower throughputs!!!).
When HARQ feedback is received from PHY in DL & UL, MAC will increase or decrease deltaMCS value based on stepsize of ACK and NACK.
On every NACK, deltaMCS is subtracted by “STEP_DOWN_FACTOR” (fixed configuration) and on every ACK reception deltaMCS is added by “STEP_UP_FACTOR” (variable RL-based adaptive value).
 The value of STEP_UP_FACTOR and STEP_DOWN_FACTOR is calculated (in terms of 100) based on the tolerance level configured from OAM in such a way that  STEP_UP_FACTOR = (STEP_DOWN_FACTOR * ACK/NACK_TDDpattern_ratio)/ 10. 
If STEP_UP_FACTOR = 1 & STEP_DOWN_FACTOR = 10 then to compensate 1 NACK, 10 ACKs are required  which is VERY slow reaction to recover the ACK condition, specially in an environment with small time coherency and frequency coherency, i.e. cell edge low SINR (SINR<15 dB) and/or high speed users. 
Correction proposal: Keep fixed the STEP_DOWN_FACTOR but make an adaptive RL-based configuration for the STEP_UP_FACTOR  such that STEP_UP_FACTOR = (STEP_DOWN_FACTOR * ACK/NACK_TDDpattern_ratio)/ 10. 
deltaMCS is always multiple of 100 (i.e. if deltaMCS = 200  200/100 = 2).

Final_MCS = (cqiBasedMcs + deltaMcs) / 100;
Ex : 
If STEP_UP_FACTOR = 3 & STEP_DOWN_FACTOR = 30.
Then it is required around 34 continuous ACKs to increase MCS by 1, & 4 continuous NACKs to decrease MCS by 1.

 NOTE : BLER Basesd MCS is calculated on every HARQ ACK/NACK reception in UL & DL.

=== Slide 12 ===
Next Steps on BLER Based Link adaptation corrections
Findings from System level Simulator
Problem1: Based on small time and frequency coherent window radio channels, the correlation between physical medium performance and upper L2/L3 user plane protocols (i.e. MAC, RLC and PDCP timers, with user service TCP/IP slow starts) is vital to be reviewed.
Solution1: need to review the L2/L3 parameters in conjunction with the micro-DeltaMCS correction algorithm to compensate for RLC-PDCP buffering and RLC-MAC scheduling/resegmentation with the LDPC coding. 
	A list of parametrers will be requested from Jio for further reviewing in order to propose some optimized values and add them to the System simulator
Problem2: Based on small time and frequency coherent window radio channels, the throughput performance on a long time window is affected by the capability of the DU module to re-segment and set the LDPC coding to the proper values in order to adapt and  compensate for the fast fading and fast changing channel conditions  
Solution2: Add a second order correction (maco DeltaMCS correction), based on a block long term (CQI multiple 160 ms periodicity based) channel prediction, using log regression or RL-based correction on CQI->MCS selection (perhaps based on some better prediction of the SINR estimation). To be proposed in next steps
Problem3: Intercell interference, mainly due to TDD interlink overshooters and synch drifting conditions, may cause sever interference (low SINR) to specific slots over a long period. This will certainly spoil the micro/macro DeltaMCS correction steps. 
Solution3: Add a third order fine-tuned channel adaptation per slot, based on a long term i.e. estimate in a period of multiple CQI report the BLER ACK/NACK performance per slot, and add micro-corrections on delta-MCS per TDD-pattern slot. 
	This is crucial to avoid slot based interference a channel disorders
